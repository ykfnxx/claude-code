# 第四章：任务管理机制

## 4.1 双重任务系统

Claude Code 包含**两个名称相同但职责完全不同的任务系统**。

### 4.1.1 运行时任务 (Runtime Tasks)

跟踪在 `AppState.tasks: { [taskId: string]: TaskState }` 中，代表正在运行的进程：

```typescript
// src/Task.ts
export type TaskType =
  | 'local_bash'         // Shell命令执行
  | 'local_agent'        // 本地Agent(子agent)
  | 'remote_agent'       // 远程Agent(CCR会话)
  | 'in_process_teammate' // 进程内teammate
  | 'local_workflow'     // 本地工作流
  | 'monitor_mcp'        // MCP监控
  | 'dream'              // 自主后台任务

export type TaskStatus = 'pending' | 'running' | 'completed' | 'failed' | 'killed'
```

**TaskStateBase** 包含所有任务类型共享的字段：
```typescript
type TaskStateBase = {
  id: string            // 类型前缀的随机ID (如 a8f3k2m1)
  type: TaskType
  status: TaskStatus
  description: string
  toolUseId?: string
  startTime: number
  endTime?: number
  totalPausedMs?: number
  outputFile: string    // 输出文件的符号链接
  outputOffset: number  // 用于增量读取
  notified: boolean     // 完成通知去重标志
}
```

**ID生成规则**:
```typescript
// 类型前缀: local_bash='b', local_agent='a', remote_agent='r',
//           in_process_teammate='t', local_workflow='w', monitor_mcp='m', dream='d'
// + 8位随机字符 (36^8 ≈ 2.8万亿组合)
// 示例: a8f3k2m1 (agent任务), b3h7j9k2 (bash任务)
```

### 4.1.2 Todo任务 (User-managed Tasks)

持久化在 `~/.claude/tasks/{listId}/` 目录中，通过工具创建和管理：

- `TaskCreateTool` — 创建任务
- `TaskUpdateTool` — 更新状态
- `TaskListTool` — 列出任务
- `TaskGetTool` — 获取任务详情
- `TaskStopTool` — 停止任务
- `TaskOutputTool` — 读取任务输出

字段包括：subject, description, status (pending/in_progress/completed), owner, blocks/blockedBy 依赖关系。

## 4.2 任务状态机

```
                    ┌──────────┐
                    │ pending  │
                    └────┬─────┘
                         │ spawn
                         ▼
                    ┌──────────┐
              ┌─────│ running  │─────┐
              │     └────┬─────┘     │
              │          │           │
         (失败)     (用户中止)    (正常完成)
              │          │           │
              ▼          ▼           ▼
        ┌──────────┐ ┌────────┐ ┌───────────┐
        │  failed  │ │ killed │ │ completed │
        └──────────┘ └────────┘ └───────────┘
              │          │           │
              └──────────┴───────────┘
                    终态 (不可转换)
```

`isTerminalTaskStatus()` 判断：`completed | failed | killed` 为终态，不再转换。

## 4.3 任务生命周期

### 4.3.1 创建 (registerTask)

`src/utils/task/framework.ts`:

```
1. createTaskStateBase() → 初始status='pending'
2. 写入 AppState.tasks[taskId]
3. emit SDK 'system/task_started' 事件
4. 初始化outputFile为transcript的符号链接
```

### 4.3.2 执行 (类型特定)

| 任务类型 | 执行方式 |
|----------|----------|
| `LocalAgentTask` | `runAgent()` async generator + ProgressTracker |
| `InProcessTeammateTask` | `inProcessRunner.ts` + AsyncLocalStorage 隔离 |
| `LocalShellTask` | 子进程 spawn + PID 追踪 |
| `RemoteAgentTask` | CCR 会话创建 + 轮询完成 |
| `DreamTask` | 自主后台任务循环 |

### 4.3.3 完成

```typescript
completeAgentTask()  // status='completed', endTime=Date.now(), 驱逐输出
failAgentTask()      // status='failed', 记录错误
killAsyncAgent()     // status='killed', 中止AbortController
```

### 4.3.4 通知

完成的任务生成 `<task-notification>` XML 消息，以 'later' 优先级入队到命令队列。Coordinator 将这些视为 "user-role messages"。

### 4.3.5 驱逐

终态任务在 `PANEL_GRACE_MS`（30秒）后被垃圾回收，或当 `notified=true` 时立即回收。除非 UI 保留显示（`retain=true`）。

## 4.4 多Agent协调

### 4.4.1 Coordinator Mode

`src/coordinator/coordinatorMode.ts` 通过环境变量 `CLAUDE_CODE_COORDINATOR_MODE=1` 激活，将主 agent 替换为协调器。

协调器 system prompt（369行）定义了完整的编排协议：

**四个工作阶段**:
```
Phase 1: Research (并行)
  ├── 多个 worker 并行研究不同维度
  └── 只读操作，自由并行

Phase 2: Synthesis (协调器)
  ├── 汇总所有 worker 的发现
  └── 制定实施计划

Phase 3: Implementation (workers)
  ├── 按文件集分配 worker
  └── 写密集型每文件集一个 worker

Phase 4: Verification (workers)
  ├── 独立验证实现结果
  └── 报告 PASS/FAIL/PARTIAL
```

**并发规则**:
- 只读任务：自由并行
- 写密集型：每文件集一个 worker
- 不相关文件集：可并行

**Continue vs Spawn 决策矩阵**:
```
                    Worker上下文与下个任务
                    高重叠        低重叠
                    ────────      ────────
Worker空闲      →  Continue     Continue
Worker忙碌      →  Spawn new    Spawn new
无活跃Worker    →  Spawn new    Spawn new
```

### 4.4.2 Agent Spawning

`src/tools/AgentTool/AgentTool.tsx` 支持三种执行模式：

**1. 同步模式** (阻塞父 turn):
```
- 在前台运行，阻塞父级
- 120秒后自动后台化 (tengu_auto_background_agents gate)
- 使用 Promise.race 竞争 agent消息 vs 后台信号
```

**2. 异步/后台模式** (Fire-and-forget):
```
- 独立 AbortController
- 返回 { status: 'async_launched', outputFile }
- 通过命令队列通知完成
```

**3. Fork 子 agent** (实验性):
```
- 继承父级的完整 system prompt + tools
- 克隆对话上下文
- 目标: prompt 缓存命中 (相同前缀)
```

### 4.4.3 Swarm 架构

`src/utils/swarm/` 实现了三层隔离后端：

```
┌─────────────────────────────────────────────────┐
│                  Backend 抽象层                   │
│          src/utils/swarm/backends/types.ts       │
├─────────────────┬───────────────┬───────────────┤
│  InProcess      │    Tmux       │    ITerm2     │
│  Backend        │   Backend     │   Backend     │
├─────────────────┼───────────────┼───────────────┤
│ AsyncLocal-     │ 独立tmux      │ iTerm2原生     │
│ Storage隔离     │ 会话面板       │ 分屏面板       │
│ 无需终端        │ 水平/垂直分屏  │ it2 CLI控制   │
│ 最轻量          │ 独立进程       │ 原生体验       │
└─────────────────┴───────────────┴───────────────┘
        ↑
   自动检测 + fallback to InProcess
```

**Team 管理**:
- 每个 leader 只能有一个 team（强制约束）
- Team 文件: `~/.claude/teams/{name}/team.json`
- 成员字段: agentId, name, agentType, model, tmuxPaneId, cwd, subscriptions
- Agent ID 确定性: `{sanitizedName}@{teamName}`

## 4.5 Agent间通信

### 4.5.1 SendMessageTool

`src/tools/SendMessageTool/SendMessageTool.ts` 支持五种路由目标：

```
┌──────────────────────────────────────────────┐
│              SendMessage 路由                  │
├──────────────────────────────────────────────┤
│ 1. In-process subagent (by name/ID)           │
│    → agentNameRegistry 查找                    │
│    → 运行中: queuePendingMessage()             │
│    → 已停止: 从磁盘transcript自动恢复           │
│                                               │
│ 2. Broadcast (to: "*")                        │
│    → 遍历team文件所有成员                       │
│    → 每个成员写入邮箱                           │
│                                               │
│ 3. Swarm teammate                             │
│    → 文件邮箱系统                              │
│                                               │
│ 4. UDS Socket (to: "uds:<path>")              │
│    → Unix Domain Socket 直接消息               │
│                                               │
│ 5. Bridge (to: "bridge:<session>")            │
│    → 跨会话 Remote Control                     │
│    → 需要用户同意                               │
└──────────────────────────────────────────────┘
```

### 4.5.2 文件邮箱系统

`src/utils/teammateMailbox.ts` 实现了基于文件的邮箱：

**存储位置**: `~/.claude/teams/{team}/inboxes/{agent}.json`

**文件锁**: `proper-lockfile`，10次重试，5-100ms指数退避

**操作**:
- `writeToMailbox` — 写入消息
- `readMailbox` — 读取所有消息
- `readUnreadMessages` — 读取未读消息
- `markMessagesAsRead` — 标记已读
- `clearMailbox` — 清空邮箱

**轮询**: `useInboxPoller` hook 定期检查新消息

### 4.5.3 结构化协议消息

所有通过邮箱传递的协议消息：

| 类型 | 方向 | 用途 |
|------|------|------|
| `shutdown_request` | Leader → Teammate | 请求优雅关闭 |
| `shutdown_approved/rejected` | Teammate → Leader | 响应关闭请求 |
| `plan_approval_request` | Teammate → Leader | 请求计划审批 |
| `plan_approval_response` | Leader → Teammate | 批准/拒绝计划 |
| `permission_request` | Worker → Leader | 请求工具权限 |
| `permission_response` | Leader → Worker | 授予/拒绝权限 |
| `sandbox_permission_request` | Worker → Leader | 请求网络访问 |
| `mode_set_request` | Leader → Teammate | 变更权限模式 |
| `team_permission_update` | Leader → Team (广播) | 同步权限规则 |
| `idle_notification` | Teammate → Leader | 通知可用性 |
| `task_assignment` | System → Teammate | 分配任务 |

### 4.5.4 命令队列

`src/utils/messageQueueManager.ts` 实现了统一的命令队列调度：

```
优先级系统:
  now  (0) — 最高优先级（用户输入、即时命令）
  next (1) — 中等优先级（默认用户输入）
  later(2) — 最低优先级（任务通知，永不饿死用户）

特性:
  - useSyncExternalStore 集成
  - dequeue(filter?) 返回最高优先级命令
  - popAllEditable() 合并可编辑命令与当前输入
  - 任务通知不可编辑（原始XML），自动处理
```

## 4.6 任务轮询与调度

### 4.6.1 轮询框架

`src/utils/task/framework.ts` 的 `pollTasks`:

```
调用间隔: POLL_INTERVAL_MS = 1000ms
每次执行:
  1. 遍历所有 running 状态的任务
  2. 读取 output 文件的增量内容 (outputOffset)
  3. 将完成通知入队到命令队列 (priority: 'later')
  4. 清理超时的终态任务 (PANEL_GRACE_MS = 30s)
```

### 4.6.2 Cron 调度

`src/utils/cronScheduler.ts` + `CronCreateTool` 实现 Cron 表达式触发：

- Cron 表达式解析
- 通过 `useScheduledTasks` hook 管理
- 触发时创建新的运行时任务

## 4.7 状态管理中的任务字段

`AppState` 中与任务相关的字段：

```typescript
{
  // 所有运行时任务
  tasks: { [taskId: string]: TaskState }

  // Agent名称注册表 (SendMessage路由)
  agentNameRegistry: Map<string, AgentId>

  // 前台任务ID (消息显示在主视图)
  foregroundedTaskId?: string

  // 正在查看的agent任务ID
  viewingAgentTaskId?: string

  // Swarm上下文
  teamContext?: {
    teamName: string
    teamFilePath: string
    leadAgentId: string
    selfAgentId?: string
    selfAgentName?: string
    isLeader?: boolean
    teammates: {
      [teammateId: string]: {
        name: string
        agentType?: string
        color?: string
        tmuxSessionName: string
        tmuxPaneId: string
        cwd: string
        worktreePath?: string
        spawnedAt: number
      }
    }
  }

  // 本地收件箱
  inbox: { messages: [...] }

  // Worker沙箱权限请求 (leader侧)
  workerSandboxPermissions: { queue: [...], selectedIndex: number }

  // 每agent的Todo列表
  todos: { [agentId: string]: TodoList }

  // Agent定义
  agentDefinitions: AgentDefinitionsResult
}
```

**输入路由** (`src/state/selectors.ts`):
```
getActiveAgentForInput():
  - { type: 'leader' }       — 默认，输入发送到主agent
  - { type: 'viewed', task } — 查看teammate transcript时
  - { type: 'named_agent' }  — 查看local agent任务时
```
